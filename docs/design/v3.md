# 新版系统设计（替代当前已上线实现）

实现落在 `cvplatform/`（部署名 platform-api / platform-worker）和 `agent/`。包名不用 `platform`，以免盖住 Python 标准库。测试在 `tests/v3/`。

仓库里现有方案和线上服务已经叫 v2。本方案是替换它的下一版，文档落在 `docs/design/v3.md`。这不是在现有 `server/` 上继续加模块。平台和 agent 分成两个代码目录、两个进程、两个部署单元。两边只通过任务表交换，不共享函数、不共享进程、不让 agent 直接写平台的表。

视频只走外部 HTTP API。当前是 AutoDL 上的 MiniMax H3。平台透传该工作流的全部字段，不用自己的标准表单把上游能力裁窄。自部署 ComfyUI 适配器、模板、GPU 机拓扑和相关页面全部删除。上游 URL 里的 `comfyui` 字样是 AutoDL 的路径，保留。

本版要解决这些事：

1. agent 抽卡图进了作品关系图，节点膨胀，几乎没有信息。
2. 成片在素材库里看不见，探索审计里也没有这些关系，产物游离。
3. 关系图分不出一张图是首帧、角色、场景还是道具。划分以槽位为准，不另做一套用途。
4. 大模型只做了 `GET /models` 式连通检查，不能确认对话是否真的可用，也不能比较模型能不能做平台自己的任务。
5. 生产路径按《漫剧 · AI 剧情短片生产流程》固化：定版资产、分段、首帧、六段式提示词、探针、逐段生成、质检、拼接。一句灵感不能直接出片。
6. 没有生成视频的图片只作为产物，不作为素材。视频也是产物。新增「产物」一栏，能按提示词搜到。
7. 平台账号和外部能力必须能填写、有示例、验证后有明确反馈。MCP 走 Agno 的标准连接，平台不内建。agent 用 Agno 写成独立服务。分段、提示词、锁段草稿各领一类任务，提示词保持短。
8. 平台代码和 agent 代码彻底分离。现有 `server/engine/generate.py`、`server/workflows/llm_step.py` 里的模型调用和提示词不再扩展，改由 agent 服务领取任务后完成。

## 两个系统

```
网页 ──▶ 平台 API ──▶ PostgreSQL（平台拥有的表）
                         │
                         │ 只读写 jobs
                         ▼
                    agent 服务（Agno）
                         │
                         ├─ Agno MCPTools ──▶ 外部 MCP 进程（stdio 或 http）
                         └─ 模型：领取响应里的短期凭证，用完即弃
```

| | 平台 `platform/` | agent `agent/` |
|---|---|---|
| 代码 | 网页、账号、素材、产物、关系、供应商配置、视频 API 调用、任务队列、工作流固化 | Agno 团队、提示词、锁段草稿、分段 |
| 依赖 | 不安装 Agno，不内建任何 MCP 服务 | 不导入平台的 `server.*` 或 `platform.*`。MCP 只通过 Agno 的 `MCPTools` 连接外部进程 |
| 数据 | 拥有全部业务表 | 没有自己的业务库。只领取任务、回写该任务的输出 |
| 部署 | `platform-api`、`platform-worker` | `agent-worker`，可单独重启、单独扩容 |

文本判断的唯一接口是 `jobs`。它不替代现有 `tasks`。`tasks` 继续负责视频、生图、下载、剪辑的资源池、槽位、`submitted` 不重复提交、`needs_attention`、取消和预算暂停。`jobs` 只承担三类文本任务：`extract_reference`、`segment_script`、`write_prompt`。固化由平台组装，不另派文本任务。

| 字段 | 谁写 |
|---|---|
| `id`、`workspace_id`、`type`、`input`、`status=queued`、`attempt=0`、`max_attempts` | 平台插入。`input` 不放密钥 |
| `status=leased`、`lease_owner`、`lease_expires_at`、`attempt` | 领取是单行条件更新：状态为 `queued`，或 `leased` 且租约已过期，并且 `attempt < max_attempts`。更新到的那一行才改这四列。没更新到行，就不能调用模型。`input` 只许平台角色更新 |
| `output` 或 `error`、`status=succeeded/failed` | 只有当前 `lease_owner`，且该行仍是未过期的 `leased`，才能回写。租约已过期，或平台已标失败、成功，晚到的回写一律拒绝，不改变该行 |
| 产物、关系、素材 | 这个任务产生的业务行，由平台在接受该任务的同一事务里写入。槽位、提升、确认分段和视频入库是平台自己的命令，不靠任务接受。agent 回传的 JSON 不直接落业务表 |

完成条件：平台单独的列 `accepted_at`。agent 把状态写成 `succeeded` 只表示「回传完毕」。平台校验通过后，在同一事务里写 `accepted_at` 和这个任务产生的业务行，并锁住这一行。`write_prompt` 的通过包含提示词校验，不只是 schema；那套校验失败时任务标 `failed`，不写产物，不写 `accepted_at`。`extract_reference` 的草稿只留在任务输出里。提升时由人提交最终原文，平台只保存这份原文，不把草稿写入素材版本。事务失败则两样都不留，这一行仍可重试。校验失败则把状态改成 `failed`，`accepted_at` 保持空。

租约等于领取响应里的凭证有效期，都是 10 分钟。agent 不心跳。现有 60 秒租约不能沿用。超过租约的回写拒绝，不改变该行。失败状态只由平台巡检写入：次数未用完改回 `queued`，可以重领；次数用完标 `failed`，错误码 `lease_expired`。过期前若要续签文件地址，只由平台改 `input.files`。

密钥不进 `jobs.input`，也不进可被业务库读者扫到的列。平台为每次领取签发一份 10 分钟内有效的调用凭证，放在领取响应里，不落库。回写结果里如果出现密钥字段，平台直接拒收。agent 的数据库角色只有 `jobs` 的领取列和回写列的 `UPDATE`，没有 `INSERT`，也没有业务表权限。

任务类型：

| 类型 | 输入 | 输出 | 不做什么 |
|---|---|---|---|
| `extract_reference` | 一张图和人给出的要点 | 待验收的锁段草稿，必须是可逐字复制的正文 | 不输出用途、坐标或外观摘要；不改已定版锁段；不建边 |
| `segment_script` | 用户给的一句想法，或已有剧本 | 分段表。每段只查七列：段号、时长/帧数、出场角色、场景和光、一个动作、台词原文、段尾状态 | 不写 `confirmed`；不标说话角色；不判断动作是否只有一个；不创建视频任务 |
| `write_prompt` | 已验收的锁段原文、分段规格、槽位 | 只填 `summary`、`detailed_description`、`overall_soundscape` | 不改写锁段，不发明标签和参数 |

保存分段表只要求原来的七列，并强制 `confirmed: false`，忽略回传里的确认标记和说话角色。是否对白为「无」而台词不是「无」，拒绝保存。是否对白确认为有、且该段台词不是「无」时，才必填说话角色。某一段没有台词，不要求本段有说话角色。旁白可以不在出场角色里，但要标成说话角色并占用音色槽。人在确认之前补标说话角色，也可以改这一段已经入库的七列。改完仍强制 `confirmed: false`，再走确认。七列改动后作废什么，只看视频调用那张表。确认时也查：为「有」且台词不是「无」，必须已经标出说话角色；为「无」而台词不是「无」，拒绝确认。确认通过后才把 `confirmed` 写成 true，确认本身不改七列。帧数只由 `17k+5` 从时长算出，不另存一份可改的帧数。

Agno 按任务类型把任务分给对应成员。领队不调用模型，也不改成员的回传。三个成员不交叉：

- 分段只接 `segment_script`。
- 提示词只接 `write_prompt`。
- 锁段草稿只接 `extract_reference`。

提示词保持短。没有「让 agent 随便改作品」这种任务。文件下载、抽帧、生图、生视频仍是平台 `tasks`，不进 MCP。

`cvgen` 保留，作为漫剧模式的创作入口。它只调平台 API，不直接写库，也不在本地保存第二份资产。手册里的中文目录树不进平台。会新建 `Reference` 或 `references` 的旧命令拒绝。设备令牌同样不能走那些旧命令。审计意见和日预算保留。网页新运行和 API v1 都只能提交九步漫剧工作流。已发布的旧版本可以打开，不能新开运行。

## 三个存放位置

| 位置 | 放什么 | 不放什么 |
|---|---|---|
| 产物 | 每一次生成的图片、视频、分段提示词、接触表、尾帧。失败的也入库，默认列表只显示成功的 | 不因为生成成功就变成可复用素材 |
| 素材库 | 人明确提升、带版本、带角色的可复用对象：主体、外形、空间、细节、风格、运镜、已定型参考图、提示模板、输出 schema | 抽卡候选、未用于成片的图、成片、接触表 |
| 关系图 | 这一段用了哪个已验收资产的哪个槽位。列从槽位推出，不另选用途 | 未验收的图、抽卡候选、接触表、没有槽位的文件 |

关系图的唯一写入者是平台。任何入口都不得新建 `Reference` 实体或 `references` 边。关系图只读分段规格里的槽位行。

必须关掉的现行入口。下表是现行 `server/` 里的调用点，加上后面五条路径，都是搬家时的删除清单。禁令只在 `platform/` 实现一次，这些路径不迁过去。正在运行的 `server/` 不另打补丁，由新进程替换。人把已验收对象放进某一段时，平台只改这一段规格里的槽位行。不新建 `Reference`，不写 `references`。

| 入口 | 现在做什么 | 改成 |
|---|---|---|
| `store_image` | 每张候选建 `Reference`，`select=first` 时连 `references` | 只写产物。人验收并指定槽位后，平台把该产物写入这一段规格的槽位行 |
| 探索任务 `pull` | 下载后直接建 `Reference` | 平台下载文件并写产物。不建实体 |
| 探索任务 `frame` | 抽帧后建 `Reference`，并连 `derived_from` | 抽帧文件写成 `frame` 产物，挂在来源视频下。不建实体，不进图 |
| `_materialize_uploads` | 上传图按 `x-role` 建成参考并连上 | 上传只写产物。人指定槽位后，平台只改这一段规格的槽位行 |
| `_apply_selections` | 人选中候选后直接建 `references` | 选定只记录人选了哪个产物。不建边，不建实体 |
| `prepare_video` 的上一镜尾帧 | 临时做成「空间」参考再塞进组合 | 不建成空间参考，不自动塞入。末帧的验收和入槽见槽位一节 |

同一条禁令还覆盖这五条路径，不能因为它们不在上表就继续建实体：

- `server/workflows/materialize.py` 的物化规则，以及工作流规格里的 `materialize`。
- 试跑占位。`server/workflows/dryrun.py` 现在会把上传图和占位图建成 `Reference`。
- 旧库导入 `server/legacy.py`。导入只保留文件和产物，不重建 `Reference` 或 `references`。
- 示例种子 `server/samples.py` 里的 `ref-zero-space`、`ref-zero-gauze`。新环境不再种这两条。
- `POST /api/works/{id}/entities`，以及 `cvgen entity add` 里会新建 `Reference` 或 `references` 的命令。

槽位行是唯一选用记录。能进槽位的是已验收产物或已验收素材，不要求另建记录。

## 产物

新表 `products`，工作区级，和 `artifacts` 一对一或一对多（一条视频产物可以挂接触表、尾帧两个文件，主文件是视频）。

| 字段 | 用途 |
|---|---|
| `id`、`workspace_id` | 主键和边界 |
| `kind` | `image`、`video`、`text`、`sheet`、`frame`、`audio` |
| `status` | `succeeded`、`failed` |
| `prompt` | 实际提交给供应商的提示词，搜索用这一列 |
| `title` | 短标题，缺省取提示词第一句 |
| `provider_instance`、`model` | 哪家、哪个模型 |
| `artifact_id` | 主文件 |
| `origin_task_id` | 产生这个文件的平台 `tasks.id`。文本产物对应 `jobs.id` 时记在 `origin_job_id`。两列分开，不混用 |
| `run_id`、`work_id` | 来源，可空。探索期单次生图没有 run 也必须有产物行 |
| `asset_id` | 提升为素材后回填。已提升的不参与回填软删除 |
| `cost_yuan`、`duration`、`resolution` | 列表上直接显示 |

关联不用产物上的单值字段：

- `product_parts`：接触表、尾帧指向视频产物。一个视频多行，不和参考图抢同一列。
- `product_inputs`：一个视频用过哪些图，多行。上限跟该实例的 `input_rules`。

写入点在平台 worker，不在 agent：

- `store_image` 每张候选只写 `artifacts` 和 `products`。未验收的候选停在产物里。
- 视频成功时写视频产物，并为每张实际提交的参考图写一行 `product_inputs`。接触表和尾帧写 `product_parts`。尾帧同时是 `kind=frame` 的产物，默认列表不展示。末帧入槽见资产一节。
- 分段提示词由平台在 `write_prompt` 被接受后写 `kind=text` 的产物。提示词列存完整六段式正文，便于按锁段里的词搜到后来的成片。

搜索：

- 网页「产物」对 `prompt` 做子串搜索，中文用 `pg_trgm`，不依赖默认分词。
- 筛选：类型、是否被某条成片的 `product_inputs` 引用、是否已提升、模型、时间。
- 默认不展示 `sheet` 和 `frame`，它们挂在视频详情里。
- 卡片显示缩略图或视频、提示词摘录、模型、花费、时间。点开能看到完整提示词、来源运行、用过的参考图、生成出的视频。

接口：

- `GET /api/products?workspace_id&q&kind&used&promoted`。`used` 查 `product_inputs`，不查产物上的标记。
- `GET /api/products/{id}`
- `POST /api/products/{id}/draft-lock` 只在人点击时派发 `extract_reference`。失败不影响已有资产。
- `POST /api/products/{id}/promote` 只接受三视图、九宫格、道具和音色。图像由人提交最终锁段原文，平台只保存这份原文，不把草稿自动写入。音色只要验收标记和版本，不要求锁段。首帧、同框比例图和成片末帧不能走这个接口。

导航在「素材库」旁增加「产物」。素材库页说明改成「只有提升过的可复用素材」。运行详情和探索分镜表链到产物，不再把候选画进关系图。

回填先写产物，再决定哪些旧实体离开关系图。提示词取值顺序是：`tasks.output.prompt`，然后是提交给供应商的正文，然后是运行的 `idea` 或 `prompt`。只读提交正文会丢掉现有成片的可搜索提示词。

「被使用」是这三处任一成立：

- 视频任务输入里引用了这个文件或实体。
- `clip_of` 能从成片走回这张图所在的镜头，并且该镜头的参考边指向它。
- `links.target_kind=asset` 的 `references` 边指向它的素材版本。

已有 `asset_id`，或已经是素材库里的一个版本：不软删除。`kick-*`、`tuner-*`、`party-*` 因此保留，即使它们没有被某次视频任务直接引用。

只软删除作品 `work_1adb1aed6c084c3e`（滑板红罐-v3）里、不满足上面三处任一条件的 `Reference` 实体。旧进程停止之后再导出这 56 个实体的 id 清单，按清单执行，不靠标题模糊匹配。其他探索作品里的主体、空间、风格、镜头保留。文件一律不删。

锁段是图像资产版本上的逐字正文。模型起草的短句不能充当锁段。一段用了什么，只看分段规格里的槽位行。

## 账号与 MCP

agent 是独立服务，不是平台里的一个包。平台负责账号和 MCP 的开关。只有 `segment_script` 需要外站材料时，agent 才连接已验证的 MCP。写提示词和锁段草稿不连接 MCP。

### 账号填写

凡是需要平台账号、密钥或 Cookie 的地方，表单必须同时有这三项，缺一不可：

- 填写：字段、是否必填、输入方式。密钥和 Cookie 用密码框，保存后只显示后四位。
- 示例：字段下方放一条可复制的假值，并写清从哪里取得。例如 GitHub token 的示例是 `ghp_` 加说明，不放真实值。
- 验证：每个表单有「验证」按钮。点下去必须返回成功或失败，失败要有原因和下一步，不能只转圈或无响应。

验证结果写回该配置的状态：`未验证`、`可用`、`失败`，并保留最近一次的时间、耗时和错误码。未验证的配置不能被 agent 调用。

### MCP

平台不内建 MCP 服务，也不包装 Agent-Reach。agent 只用 Agno 的 `MCPTools` 连接已经在运行的外部 MCP。这些进程可以是 Node、Python 或 HTTP，由各自的部署提供，平台不实现它们的工具。

设置里一张 MCP 卡片对应一个外部服务：传输（stdio 命令或 HTTP 地址）、名称、启用开关。卡片必须有填写、示例和验证。验证是一次普通 MCP 握手，列出工具；失败显示错误原文和下一步。平台不安装 Agno，也不为了验证去调用 Agno。未验证或已停用的卡片，agent 领取任务时不会连上。

卡片只保存连接地址和开关，不保存外部进程自己的登录。该次调用需要的工作区凭证放进领取响应的短期参数，不写入外部进程的全局配置。未验证的 MCP 不参与任何 `jobs`。依赖外站材料的 `segment_script` 在对应 MCP 未验证时不创建。文件下载仍由平台 `tasks` 做。

## 大模型探测和性能测试

现有 `POST /api/admin/providers/{name}/probe` 对大模型只请求 `/models`。这只能说明地址通，不能说明对话通。

探测按协议分开，不能只改三个文本协议：

- `openai-chat`、`openai-responses`、`anthropic-messages`：发送用户消息 `hi`。返回回复正文、耗时、实际模型名、token 用量或错误原文。
- 生图：对 `/v1/images/generations` 发一次最小请求，`response_format` 为 `b64_json`。返回里有图片字节才算通过。只测地址，或只做文字描述，不算通过。
- `openai-audio`：发送一句固定短文本，确认返回音频头。
- `minimax_h3_803`：鉴权固定为裸 token，不加 `Bearer`。实例工作流 id 不是这个值时不探测。探测是 `GET /api/v1/comfyui/workflows/minimax_h3_803`，成功则缓存返回的 `input_rules`。不提交生成，也不查询一个不存在的任务号。
- 设置页按钮按协议显示动作。文本模型是「发送 hi」。失败必须显示错误原文。
- `GET /providers/{name}/models` 仍只负责列模型，不代替探测。

性能测试用平台真会派发的三份契约，题目和 schema 放在 `platform/benchmarks/cases/`，不放在 `server/`：

| 题 | 输入 | 通过线 |
|---|---|---|
| `extract_reference` | 一张图和人给出的要点 | 回传是可逐字保存的锁段正文，不是用途或坐标 |
| `write_prompt` | 一段已验收锁段、分段规格、槽位 | 只回传三段。平台拼上的锁段与资产版本逐字相同，这三段里不再出现 `subject_definitions` |
| `segment_script` | 只有一句话 | 回传七列分段表，且不包含视频任务 |

视觉题必须把图放进请求。没有视觉能力的实例，第一题直接记「不适用」，不记成失败，避免换模型时被一道它做不了的题拉低。运行前按实例单价和题目的最大 token 显示预计花费，确认后才调用。单价缺失则不许开始。结果写入 `llm_benchmarks`。

## 漫剧生产流程

V3 的已发布生产流就是手册里的九步，当前一集要能按这本手册逐段跑完。分段表先保存，同框比例随后补。分段规格由该段的 `confirmed` 确认，不再单列一步。这不是「一句灵感出片」，也不是一段自由文本直接出片。手册是执行规则。平台负责闸门、版本和文件；`cvgen` 负责按这个顺序创作；平台 agent 只填平台派下来的文本任务。跑通一集之后，平台把可复用的资产和槽位规则固化成工作流版本。手册里的中文目录树不进平台。

### 谁做什么

| 步骤 | `cvgen` | 平台 | 平台 agent |
|---|---|---|---|
| 0 资产定版 | 上传或触发生图，提交验收 | 图像资产存版本和逐字锁段；音色只存验收标记和版本 | 只在人点击时，从未验收图起草锁段。草稿不是锁段 |
| 1 剧本分段 | 先确认是否对白，再补标说话角色。复查不过时改七列，确认时勾过「只有一个动作」 | 保存和确认都查是否对白。七列改动后的作废见视频调用 | 只回传七列，不标说话角色 |
| 2 同框比例 | 分段表保存后提交同框比例 | 按分段表算出的角色对计算差值并保存同框图 | 不看图，不填数字 |
| 4 分镜首帧 | 触发生图，或选用已验收末帧 | 首帧是产物。验收后可进槽位，不进素材库。末帧入槽见资产一节 | 不看图报成功 |
| 5 提示词 | 请求为某一段写提示词 | 把已定版锁段原文放进任务输入，并校验回传 | 只写骨架里锁段以外的三段 |
| 6 探针 | 在 1 到 5 秒内确认时长后提交 | 提交该段已保存的 seed。分辨率、模式和缺 seed 的拒绝见视频调用。这一段未过，不能排这一段的正式任务 | 不提交视频 |
| 7 正式分段 | 提交该段 | 只认最近一次探针结果上的勾选 | 不提交视频 |
| 8 质检 | 标记不合格的段 | 先作废该段 G3 和 G4。没改字段也要等新探针被勾过 | 不改判 |
| 9 拼接 | 请求拼接 | 每段 G4 都通过后才拼接。分段已是确认的 1088×1920 时，按整集确认画幅输出，本流程可以确认为 1080×1920。这是唯一允许的缩放。其他尺寸停住。各段请求时长之和必须等于单集时长。吸附后的实际时长不拿来对单集时长。调色、字幕、铺乐、响度各有确认值，可以是「无」。未确认才停住。成片进产物 | 不调用 ffmpeg |

缺资产、缺画幅、缺段时长、缺模式、缺是否对白，平台停在对应闸门。这些字段可以带保守默认，但必须是 `confirmed: false`。未确认等于缺失。人确认后才改为 `true`。画幅、段时长和模式的确认值不能是「无」。可以是「无」的只有是否对白，以及调色、字幕、铺乐、响度。单集时长只用来核对各段之和，不作为 H3 的 `duration`。

第 0 步未验收时，第 4 步及之后全部停住，不能开始生成。分段表保存时强制 `confirmed: false`，可以入库。缺列或超过 15 秒拒绝保存。是否对白为「无」而台词不是「无」，拒绝保存。是否对白未确认时不能确认分段。`confirmed` 仍为 false 时，这一段不能进入第 4 步及之后。是否对白改为「有」或「无」时，立刻复查全部分段。复查不过，该段 `confirmed` 回到 false，G1 回到未通过。人改这一段七列后，仍强制 `confirmed: false`，再走确认。改为「有」时，台词不是「无」却没有说话角色或已验收音色，第 4 步停住。改为「无」时，任一段台词不是「无」，第 4 步停住。同框比例在分段表保存之后补，第 5 步之前检查。

G1 是一集一条。G2、G3、G4 是每段一条。固化时，G1 和每一段的 G2、G3、G4 都必须通过。

| 闸门 | 记录什么 | 不过则停在 |
|---|---|---|
| G1 资产 | 一集一条。人勾选图像项：三视图三视角一致；九宫格机位无矛盾；锁段文字与图一致。说话角色标出后重新检查音色：每个说话角色都要有已验收音色，缺了则第 4 步及之后停住。是否对白改为「无」时复查全部分段，任一段台词不是「无」则 G1 回到未通过。第 0 步的图像勾选不能代替这两次检查 | 第 4 步及之后 |
| G2 分镜 | 每段一条。人看首帧后勾选：角色像不像，构图是否符合该段动作。平台只保存勾选结果 | 该段第 6 步 |
| G3 探针 | 每段一条。每次新的探针都作废上一次的 G3。勾选记在这一次探针结果上，不记在可复用的请求体上。人看这次成片后勾选：身份守住、声音对（不串音、不静音）。画幅对的是这次提交的分辨率，不是正式段的 1088×1920。第 7 步只认最近一次结果上的勾选 | 该段第 7 步 |
| G4 成片 | 每段一条。人看成片后勾选：身份一致；无意外人声或杂音；台词与口型大致对得上。第一段不检查接缝。从第二段起，人对照上一段末帧和本段首帧后勾过。平台只保存勾选结果。第 9 步要求每段都通过 | 该段不能进入拼接 |

### 资产和锁段

角色三视图、场景九宫格、道具图、音色小样都是带版本的素材。锁段是该版本上的逐字文本，不是模型可改写的摘要。升版本才允许新图或新锁段，旧版保留。

只有三视图、九宫格、道具和音色提升为素材。首帧、同框比例图和成片末帧验收后仍是产物，可以进入槽位，不进入素材库。锁段原文放在图像素材版本里。音色素材没有锁段。

一段的槽位是一张列表，不是写死的两个角色。每一行由人指定种类：首帧、角色、场景、道具、音色。`ref_image_0` 不参与固定编号，每段换成该段首帧或上一段末帧。角色、场景、道具的编号在该资产第一次入槽时分配，全剧固定，不按本段出场重排。同一编号可以升版本，不能换成另一个资产。同一资产不能占两个编号。空槽占编号。锁段拼接不按槽位行逐行输出，空槽不占 Subject 行。本段没有的槽留空，不塞占位图。有图的槽保持自己的固定序号。数量不超过该实例 `input_rules` 的上限。这张对照表钉进发布版，下一集沿用，不重新分配。

下一段要用上一段末帧当 `ref_image_0` 时，不重新生图。平台在成片下载后抽出末帧，写成 `kind=frame` 的产物。人用验收命令验收首帧、同框比例图或末帧。验收后才能写入槽位。未验收的末帧不能入槽，平台也不自动塞入。这三样不能提升。

角色序号从 1 起，全剧固定。图像是 `ref_image_k`，声音是 `ref_audio_{k-1}`。手册里角色 A 的图像是 `ref_image_1`，声音是 `ref_audio_0`，标签是 `<Audio 1>`。不能把「音频槽使用同一个角色编号」做成 `ref_audio_1`。场景和道具没有音频槽。人把场景指定为 `ref_image_3` 时，标签是 `<Picture 4>`。`ref_image_2` 为空时，场景仍是 `<Picture 4>`，不能变成 `<Subject 2>`。`ref_image_N` 对应 `<Picture N+1>`，`ref_audio_N` 对应 `<Audio N+1>`。

序号就是槽位的固定编号。空槽占编号，但不输出 Subject 行，提示词不得引用该序号。有图的槽保持自己的固定序号，不重新编号。`ref_image_0` 只输出 `<Picture 1>` 和起始句，不输出 `<Subject>`，也不要锁段。空的图像槽不输出 `<Picture>` 和 `<Subject>`。`ref_image_2` 为空时，不写出 `<Subject 2>`。场景若在 `ref_image_3`，锁段仍贴 `<Picture 4>` 和 `<Subject 3>`，不能贴成 `<Subject 2>`。音色槽有文件时，仍输出对应的 `<Audio>`。旁白只有声音、没有图像，也走这一条：由人指定音色槽，不占图像编号。未定义的标签一律拒绝。只检查 `<Picture N>` 不够。

`ref_image_0` 为空不能探针。是否对白为无时，每一段台词都必须是「无」。为有、且该段台词不是「无」时，分段表标出的每个说话角色都要有已验收音色和对应音色槽，否则不能探针。台词是「无」的段不要求说话角色。旁白标成说话角色并占用音色槽。平台不从台词原文猜测说话人。

关系图直接读这段槽位列表，列从种类推出。不再另维护一份选用记录。未验收的抽卡不出现在槽位里，也就不出现在图里。

同框比例在分段表保存之后、指定槽位之前提交。命令列表也按这个顺序，不能先交同框比例。同一段有 n 个出场角色时，必填的是这 n 个角色的全部组合。「才配一对」不能做成每段只交一对。多段重复出现的同一对只记一对。平台只计算差值并保存同框图，不从图片里测量。分段表还没保存时，对数没有来源，拒绝提交。只填数字、不从分段表得出组合，不能进入第 5 步。对数不足、任一对差值大于 10%，或只勾选通过，也拒绝。两人同段正好一对。三人同段要有三对。零对只在没有任何一段有第二角色时通过。

### 视频调用

- 基址来自该供应商实例。这一集要开跑，实例上的工作流 id 必须是 `minimax_h3_803`。现在线上的 `minimax_h3_zm_u24` 不能开跑。
- 这个工作流的鉴权固定为裸 token，不加 `Bearer`。
- 字段和取值范围以该实例缓存的 `input_rules` 为准。平台不把手册里的枚举再写死一遍。`input_rules` 拉取失败时，正式生成停住。
- 提交体仍按透传：平台知道的文件换成 data URL，其余字段原样送出。结果 URL 有时效，平台拿到后立刻下载入库。
- 首帧和尾帧是提交参数，不是关系图节点，也不能被适配器丢掉。`minimax_h3_803` 的首帧就是必填的 `ref_image_0`。它的 `input_rules` 里没有尾帧字段；成片下载后抽出的末帧，只作为下一段的 `ref_image_0`。其他工作流的 `input_rules` 若有首帧或尾帧字段，平台必须原样送出，不能只送 `ref_image_0`。空的首帧不能提交。
- seed 在探针前由人提交，写进分段规格。没有 seed 就拒绝探针。平台不自行生成 seed。探针和正式段提交这同一个 seed。第 7 步不再补一个新 seed。
- 正式提交使用分段规格里的时长、画幅和模式，以及同一 seed 和已验收提示词。正式提交不读探针保存的分辨率、模式和时长。时长范围 1 到 15 秒，始终是正式段时长。单集时长只用来核对各段请求时长之和。画幅、段时长和模式的确认值不能是「无」。
- 探针时长由人在 1 到 5 秒内确认。分辨率和模式从 `input_rules` 里取最低一档和高速模式。枚举对不上这两个名字时停住，显示枚举，由人确认探针用哪一档。保存的对象就是分辨率、模式和时长，不叫提交体。不写回分段规格，也不保存勾选、首帧或 seed。重新探针只复制这三项，另建结果。首帧、seed 和勾选不随这三项再交。探针不改已验收提示词，也不改 seed。
- 每次新的探针都作废上一次的 G3。勾选只写在这一次结果上。第 7 步只看 G3，只认最近一次结果上的勾选。第一段也用这一条。标记不合格时，先作废该段 G3 和 G4。字段改动的作废以这张表为准。表前不另列首帧、槽位、资产版本或 seed，那一句不能单独执行。

| 改了什么 | 还作废 | 下一步 |
|---|---|---|
| 没改槽位、资产版本和 seed | 不在这一行处理 | 只复制已保存的分辨率、模式和时长，另建一次探针结果。这一行不保留、也不恢复 G3。正式提交只认这次新结果上的勾选 |
| 角色、场景或道具的图像版本 | 该段首帧、提示词、G2、G3、G4。只升角色、场景或道具的资产版本时，旧的「像不像」也作废 | 先重出首帧，验收后再写入 `ref_image_0`，然后才能勾 G2。旧首帧留在槽里时不能探针。之后再重写提示词，再探针。只升音色版本时，G2 保留 |
| 只改首帧 | 该段提示词、G2、G3、G4 | 新首帧先验收并写入 `ref_image_0`，再勾 G2，再重写提示词，再探针 |
| 出场角色或场景 | 该段首帧、提示词、G2、G3、G4，以及同框比例 | 按新的出场角色重算同框比例。槽位里的角色与新的出场角色一致。重出首帧，验收后写入 `ref_image_0`，再勾 G2，再重写提示词，再探针。旧首帧留在槽里不能探针 |
| 动作 | 该段提示词、G2、G3、G4 | 人重新看当前首帧。勾过 G2 之后才重写提示词，再探针。勾不过就重出首帧，验收后写入 `ref_image_0`，再勾 G2，再重写提示词，再探针。旧提示词不能进探针 |
| 台词 | 该段提示词、G3、G4。G2 保留 | 先重写提示词，再探针 |
| 时长 | 该段提示词、G2、G3、G4 | 人按新时长重看当前首帧。勾过 G2 之后才按新时长重写，再探针。勾不过就重出首帧，验收后写入 `ref_image_0`，再勾 G2，再重写，再探针。已接受的提示词不能跳过这道时间码重验。帧数只由 `17k+5` 从时长算出，不另存一份可改的帧数 |
| 段尾状态 | 该段提示词、G3、G4。有下一段时，下一段的提示词、G2、G3、G4 也作废 | 本段先重写提示词，再探针，再出片并抽出新末帧。有下一段时，新末帧验收后写入下一段的 `ref_image_0`，再勾 G2，再重写提示词，再探针。本段新末帧未入槽时，下一段不能探针。最后一段没有下一段，只作废本段 |
| 音色槽增删 | 该段提示词、G3、G4。G2 保留 | 先重写提示词，再探针。新的 G3 勾过之后才正式提交 |
| 只改 seed，或只升音色版本 | 该段提示词、G3、G4。G2 保留 | 先重写提示词，再探针 |
- 生图走 `/v1/images/generations` 和 `/v1/images/edits`，请求带 `response_format: b64_json`。返回 URL 不作为成功，因为那类地址本机不可达。
- 台词只写在提示词的 `<d>` 里。`ref_audio` 只迁音色。这条生产流不调用 IndexTTS，避免同一句台词有两个声音来源。

### 提示词

六段式骨架保留。`subject_definitions` 只拼角色、场景、道具里有图的槽，按固定序号各写一行已验收锁段原文。空槽不占这一行，也不把后面的锁段前移。`<Subject N>` 的 N 就是该槽固定编号。首帧只输出 `<Picture 1>` 和起始句，不进这段，也不要锁段。空的图像槽不输出 `<Picture>` 和 `<Subject>`，提示词不得引用该序号。音色槽有文件时仍输出对应的 `<Audio>`。角色声音按 `ref_audio_{k-1}` 绑定，不按角色编号直接写成同号音频槽。agent 和 `cvgen` 都不能改写。agent 的 `write_prompt` 只填 `summary`、`detailed_description`、`overall_soundscape`。`retention_analysis` 只覆盖这些有锁段的槽和有文件的音色槽。`non_diegetic_music` 固定 `N/A`。

`write_prompt` 只回传三段，回传里没有锁段字段。平台把锁段按上面的槽位顺序拼到这三段前面，得到完整提示词，再校验这份全文。校验失败时任务标 `failed`，不写产物，不写 `accepted_at`，这一段不能进入探针：

- 拼好的全文里，锁段与该资产版本逐字相同。这三段里不得再出现一份 `subject_definitions`。
- `<Picture 1>` 只指向 `ref_image_0`，并且没有对应的 `<Subject>`。其余 `<Picture N>` 正好对应有图的 `ref_image_(N-1)`，`<Audio N>` 正好对应有文件的 `ref_audio_(N-1)`。角色 k 的声音只进 `ref_audio_{k-1}`，不能写成 `ref_audio_k`。`<Subject N>` 的 N 就是角色、场景或道具槽的固定编号。空号和首帧不得出现在 `subject_definitions`。未定义的标签拒绝。
- 英文检查只覆盖 `summary`、`detailed_description`、`overall_soundscape`，并排除 `<d>` 和锁段。锁段里的中文不参与这道检查。`<d>` 内保留原语言对白，也不计入词数。
- 排除 `<d>` 之后的 `detailed_description` 为 350 到 500 个英文词。
- 时间码是三位小数、严格递增，并且不超过正式段吸附后的实际时长。探针时长不参与这道校验。正式段可以是 10 秒，探针可以是 1 到 5 秒，两者用同一份已验收提示词。
- 帧数按 24fps 吸附。k 是最小整数，使 `17k+5` 不小于请求秒数乘以 24。实际时长是这个帧数除以 24。1 到 15 秒都用这个公式。请求 10 秒得到 k=14、243 帧，上限是 243/24 秒，不是 175 帧。
- 额外负面约束不超过 3 条。`no burned-in text, no subtitles, no watermark` 和固定英文句 `The grid lines and labels of the reference board do not appear in the picture.` 不计入这 3 条。有场景槽时，这句必须逐字出现。
- `non_diegetic_music` 为 `N/A`。音频槽位的说明只迁音色，不带台词。

校验失败时，平台把错误码写入该任务。下一次同一段的 `write_prompt`，输入里带上这些错误码。词数、标签对应和缺少那句固定英文分格线句子，都属于这组错误码。

### cvgen

`cvgen` 增加漫剧命令，按手册步骤调用平台，不在本地保存第二份资产。命令顺序是：查看缺什么、提交资产、请求锁段草稿、勾选 G1、确认是否对白、提交分段、补标说话角色、修改分段七列、确认分段、提交同框比例、指定槽位编号、触发生图、验收产物、把已验收对象写入槽位行、勾选 G2、提交 seed、请求提示词、提交探针、勾选 G3、提交正式段、标记质检、请求拼接。勾选 G1 在触发生图之前。勾选 G2 在首帧入槽之后、提交探针之前。勾选 G3 在探针之后。G4 由标记质检写入。验收产物的对象是首帧、同框比例图和末帧。确认分段前，是否对白必须已确认，人还要勾过「这一段只有一个动作」。确认通过后才把 `confirmed` 写成 true。固化由平台完成，没有让 agent 另写规格的命令。

每条命令的输出只说明平台闸门停在哪一步、缺哪一项。它不在本地拼 H3 请求，也不保存 token。确认不改七列。修改七列是另一条命令。重跑顺序见视频调用。没有保存的分辨率、模式和时长，就不能比较这三项。重新探针只复制这三项，另建结果。正式提交不读这三项。同框比例排在提交分段之后。新一集要等 `segment_script` 被接受、分段表保存之后，确认命令才有对象。

### 固化

一集的 G1 通过，且每一段的 G2、G3、G4 都通过后，平台组装工作流草稿。agent 不另写一份。发布版只钉资产版本、人指定的编号对照表、供应商实例和 `input_rules` 摘要。分段表和提示词属于这一集，不钉进发布版。发布后不可改。重跑这一集用这一集的已验收记录。

发布版要求带剧本，并停在未确认分段。新一集没有现成的分段可确认。API 提交这个发布版并带上剧本后，创建 `segment_script`。没有剧本就不创建这条任务。接受后保存分段表，`confirmed` 强制为 false。保存只要求原来的七列。是否对白确认为有、且该段台词不是「无」时，才必填说话角色。某一段没有台词，不要求本段有说话角色。旁白可以不在出场角色里，但要标成说话角色并占用音色槽。不复制上一集的分段、提示词、探针和闸门。确认命令要等这张表保存后才有对象。未验收或未确认的步骤停在对应闸门。

现有「H3 通用参考短片」不发布。它的物化名字和这套槽位、锁段都对不上。

提交前估价覆盖本运行全部付费步骤：生图按张、探针和正式片按各自秒数、模型按 token 上限。单价缺失才拒绝。本机 ffmpeg 拼接可以估成 0。

## H3 提交体

正式提交体只有一份。槽位文件由平台换成 data URL。正式提交使用分段规格里的时长、画幅和模式，以及同一 seed 和已验收提示词，不读探针保存的三项。探针保存的对象就是分辨率、模式和时长，不叫提交体，不写回分段规格，也不含勾选、首帧或 seed。重新探针只复制这三项，另建结果。`input_rules` 里的首帧、尾帧和其他新增字段原样带上，不另做一份 `upstream`。`minimax_h3_803` 没有尾帧参数，首帧就是 `ref_image_0`。末帧入槽见资产一节。

适配器不再把某个旧工作流的限制写成死规则。字段缺失、取值非法、鉴权格式错误，都显示上游原文。核价只在漫剧流程那一节规定，这里不另写一套单价。

## 放弃 ComfyUI

删除或停止使用，启动后不得再登记 ComfyUI：

- `server/providers/comfyui.py`，`providers/__init__.py` 的协议注册，`worker.py` 对 `comfyui` 实例的探活。
- `instances.py` 启动种子里的 `video.comfy-gpu1`，以及 `samples.py` 的 `comfy-wan-i2v`。
- 工作流校验、`docs/design/workflow.v1.schema.json`、`server/workflows/workflow.v1.schema.json` 里把 `video.comfy` 写成合法供应商的说明和分支。
- 素材类型 `comfy_template`。`product-ad` 改为走 H3 透传，或从示例和测试夹具里换成漫剧分段流程。不能只删示例而留着红色测试。
- 网页 `labels.js`、`comfy.js` 里把 `comfyui` 当作协议的列表。关系图颜色移到不依赖该文件的模块。
- 部署说明里的 GPU 机和池 `gpu1`。

已发布且钉死的工作流版本若含 `comfyui`，不改历史 JSON。重跑时平台拒绝并提示「该版本使用已移除的视频协议，请另存一版」。线上 `video.comfy-gpu1` 迁移时删除，不只是禁用，避免种子逻辑把它找回来。

视频供应商只保留 `video.autodl-h3` 和以后新增的 HTTP 视频协议。
