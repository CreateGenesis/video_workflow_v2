# cvgen v2 设计方案

状态：草案，待评审。日期：2026-10-22。

配套文件：
- `workflow.v1.schema.json`：工作流规格的结构校验（JSON Schema 2020-12）。
- `examples/product-ad.workflow.json`：产品广告，关键帧走生图 API，视频走自部署 ComfyUI，带人工闸门。
- `examples/zero-snow.workflow.json`：从现有“你就叫零”雪原段定型，视频走 autodl H3。
- `examples/schema-four-beat-shot.output.json`：雪原段大模型步骤的输出 schema。

## 0. 定位

| 阶段 | 谁主导 | 人做什么 | 产物 |
|---|---|---|---|
| 探索 | agent 通过 `cvgen` 操作 | 审计：看过程、看花费、审批、留意见 | 一个作品，以及定型后的工作流草稿 |
| 定型 | agent 写工作流 JSON，试跑 | 审工作流版本，发布 | 已发布的工作流版本（不可变） |
| 生产 | 无 agent，服务端自动执行 | 填灵感、发起运行（可批量）、按需审批、审片、下载 | 成片；也可被其他服务通过 API 调用 |

## 1. 已定决策

| 项 | 决定 |
|---|---|
| 灵感变分镜 | 服务端内置大模型步骤，支持 OpenAI Chat、OpenAI Responses、Anthropic Messages 三种协议 |
| 工作流格式 | JSON，结构见 `workflow.v1.schema.json` |
| 视频生成 | 现有 autodl H3（按次计费）；后期自部署 ComfyUI API |
| 生图 | 依赖外部 API，不占自部署 GPU |
| 数据库 | PostgreSQL，同时承担任务队列，不引入额外消息中间件 |
| 使用范围 | 公司内部，多人使用，需要角色区分 |
| 部署 | 应用机与 GPU 机分离 |

## 2. 部署拓扑

```
应用机（内网）                                         GPU 机（可多台）
┌──────────────────────────────────┐                 ┌───────────────────────────┐
│ web + api（无状态，可多实例）      │                 │ ComfyUI :8188             │
│ worker（可多实例）  ───HTTP / WS──┼── 内网/WireGuard ──▶ /prompt /ws /history /view│
│ PostgreSQL                       │                 │ 模型、自定义节点            │
│ RustFS（S3）                      │                 │ 定时清理 input/output 目录  │
└──────────────────────────────────┘                 └───────────────────────────┘
          │ HTTPS 出站
          ▼
外部 API：大模型、生图、autodl H3、配音
```

- GPU 机只跑 ComfyUI，不连 PostgreSQL，也不连对象存储。worker 负责上传输入图（`/upload/image`）、提交、收进度、拉产物（`/view`）、写入对象存储。换 GPU 机或加机器，只需要在网页上登记一个供应商实例。
- ComfyUI 自身没有鉴权。只允许应用机访问：防火墙白名单、WireGuard 或 SSH 隧道三选一，可选在前面加一层带 token 的反向代理。云上租的 GPU 机同样走隧道，不直接暴露公网。
- 健康检查：worker 每 30 秒调一次 `/system_stats`。连续失败则暂停该机器的资源池；已领取但未提交的任务退回队列；已提交的任务在机器恢复后按上游任务号找回。
- 环境一致性：ComfyUI 模板声明它用到的节点类和模型文件。登记机器时和发布工作流时，都用 `/object_info` 核对，缺节点或缺模型的机器不进该模板的可用列表。
- GPU 机磁盘：ComfyUI 的 input/output 目录会一直增长，在 GPU 机上放一个定时清理任务（产物已经由 worker 拉回对象存储）。

## 3. 核心概念与数据模型

### 3.1 概念

| 概念 | 说明 |
|---|---|
| 工作区 | 项目或团队的边界。素材、作品、工作流、运行都属于某个工作区 |
| 素材库 | 工作区级、带版本、可跨作品复用。包括本体实体（风格、主体、外形、场景、细节、运镜、情绪、音色、参考图），以及提示模板、输出 schema、ComfyUI 模板、配乐 |
| 作品 | 一张本体实例图。探索期由 agent 搭；每次运行也会生成一个作品（`origin = run`），便于审计和重跑 |
| 工作流 / 版本 | JSON 规格。草稿可改；发布后不可变；运行钉死版本 |
| 运行 | 工作流版本 + 输入 → 产物。可以成批发起 |
| 任务 | 队列里的最小执行单元 |
| 闸门 | 运行中的审批点 |
| 事件 | 只追加的审计日志，每条都有操作者 |
| 花费台账 | 每个任务的用量与金额，区分估算和实际 |

原则：服务端没有任何全局“当前选中”。每个请求显式带工作区、作品或运行。CLI 在本地配置里记住当前作品，并在每次请求时带上。

## 4. 工作流规格 v1

### 4.1 顶层结构

| 字段 | 说明 |
|---|---|
| `schema` | 固定为 `cvgen.workflow/v1` |
| `inputs` | 对象型 JSON Schema。生产台表单、服务 API 的输入校验都由它生成。`format: asset-upload` 表示上传文件，`x-role` 指定上传图的参考用途 |
| `assets` | 别名 → `asset:名称@版本`。必须钉死版本，不允许 latest |
| `defaults` | 分辨率、时长、优先级 |
| `budget` | 必填，至少有 `max_yuan` |
| `policy` | `batch_barrier`、`gpu_order`（run_first / round_robin）、`on_budget_exceeded` |
| `nodes` | 步骤列表，依赖用 `after` 和取值路径隐式推出 |
| `outputs` | 对外交付的产物名 → 节点路径 |

### 4.2 模板与取值

- 只有一种语法：`{{路径}}`。路径的根是 `inputs`、`assets`、`run`、`item`，或某个节点 id。没有条件、循环和函数，保证规格能静态检查。
- 解析结果按使用位置决定：
  - 在文本里：文本类素材（提示模板）取正文；实体类素材取标题；`{{assets.style.medium}}` 取字段；列表按“、”连接。
  - 在 `links.to`、`references`、`attach_to` 里：解析成实体或素材引用；列表展开成多条。
  - 在 `output_schema` 里：解析成 schema 对象。
- `for_each` 指向一个列表时，每项展开成一个任务，模板里用 `{{item}}`；指向单个对象时只有一项。
- 节点之间的依赖：显式的 `after`，加上模板和 `for_each` 里引用到的节点，两者取并集。
- 条目级依赖：两个节点对同一个列表做 `for_each`，并且有依赖关系时，按条目一一对应，第 i 镜的视频只等第 i 镜的关键帧。闸门是整体屏障，要等它 `after` 的节点全部条目完成。

### 4.3 节点类型

| 类型 | 作用 | 要点 |
|---|---|---|
| `llm` | 大模型结构化输出 | `materialize` 把输出写成本体实体并建关系；写完后对每个镜头跑一次组合，组合警告与 schema 错误一起进入修复循环（`repair` 次） |
| `image` | 生图 | `candidates` 张候选；`select: gate` 交给后续闸门挑；`attach_to` 把选中的图作为参考连到实体 |
| `video` | 生视频 | `prompt: compose` 由本体组合四段式提示词（现有 `compose.py`）；ComfyUI 供应商必须给 `template`；`continuity: previous_last_frame` 时同一运行内镜头自动串行 |
| `tts` / `music` | 配音 / 配乐 | |
| `check` | 自动检查 | 时长、分辨率、响度、接触表、尾帧、台词；失败时可以只重跑对应的上游条目 |
| `edit` | ffmpeg 剪辑 | `join`、`mix`、`subtitle`、`export` |
| `gate` | 闸门 | 审批角色、是否自动通过、能否驳回单个条目、超时策略 |

`materialize` 的语义：
- 列表字段每项一个实体，并保留顺序；子字段按 `children` 规则另建实体，不拷进父实体。
- 实体按 `ontology/types.md` 校验必填字段；关系按 `ontology/relations.md` 校验起止类型（例如 `styled_as` 只能是镜头 → 风格）。
- `contains`、`belongs_to` 由服务维护，规格里不能写。

### 4.4 校验

1. 结构：`workflow.v1.schema.json`。
2. 语义：
   - 节点 id 唯一；`after` 和取值路径都能解析；步骤图无环。
   - 素材存在且版本存在；供应商实例存在，且能力与节点类型匹配；ComfyUI 模板的节点和模型在至少一台可用机器上齐全。
   - `inputs` 通过 JSON Schema 元模式校验；输出 schema 落在三种协议都支持的子集内（见第 5 节）。
   - 本体约束：一个镜头最多一种运镜，参考用途在枚举内，时长为 1 到 15 的整数，分辨率在档位内，参考图总数不超过上限。
   - 按次计费且不可安全重试的供应商，`retry.max_attempts` 强制为 1。

### 4.5 试跑

| 档位 | 做什么 | 花钱 |
|---|---|---|
| `compile` | 大模型节点用 `fixtures` 里的样例输出，编译出全部最终提示词和花费估算 | 不花 |
| `llm` | 真实调用大模型，编译出全部视频提示词 | 只花大模型的钱 |
| `trial` | 完整运行一次，产物标记为试跑；成功后的大模型输出可以存成新的 `fixtures` | 全额 |

验收基线：雪原段的 `compile` 试跑，输出的提示词要和现有 `compose.py` 对同一组实体的结果逐字一致。

### 4.6 生命周期

1. agent：`cvgen workflow draft save spec.json --from-work <作品>`。
2. agent：`validate`、`dry-run --level compile|llm`、`trial`。
3. 审计员在网页上看：与上一版的差异、试跑提示词、试跑产物、花费估算 → 发布。
4. 运行钉死版本。旧版本可以下线，但不删除。

agent 不能发布，也不能修改已发布版本。

## 5. 大模型步骤

| 协议 | 接口 | 结构化输出 |
|---|---|---|
| `openai-chat` | `/v1/chat/completions` | `response_format: {type: json_schema, json_schema: {name, schema, strict: true}}`；不支持时退到工具调用，再退到 `json_object` |
| `openai-responses` | `/v1/responses` | `text.format: {type: json_schema, name, schema, strict: true}`；不支持时退到工具调用 |
| `anthropic-messages` | `/v1/messages` | 强制工具调用：`tools: [{name, input_schema}]` 加 `tool_choice: {type: tool, name}`，从 `tool_use` 块取结果。强制工具调用时不开启 extended thinking（两者不兼容） |

- 每个实例单独配置 base_url，官方接口、兼容网关、自部署推理服务都能接。实现上用官方 `openai` / `anthropic` SDK，改写 base_url。
- 能力标记：`json_schema`、`tools`、`vision`、上下文长度。探测接口尝试填写，管理员可以手动改。
- 输出 schema 的兼容子集：所有字段都列进 `required`，`additionalProperties: false`，可选值用 `null` 联合类型。字数、条数等范围约束可能被上游忽略，一律由服务端 jsonschema 二次校验。
- 修复循环：schema 错误或组合警告 → 把错误原文追加为新一轮消息，最多 `repair` 次；仍失败则任务进入 `needs_attention`，网页上能看到每一轮的原文。
- 审计：完整请求、原始响应、token 用量、耗时、花费、提示模板版本，全部写进任务输出和事件。
- 缓存：按（实例、模型、消息、schema、参数）计算哈希；试跑和重跑命中缓存时不再调用。可以在节点上关闭。
- 密钥：PostgreSQL 里加密存储，主密钥来自环境变量 `CVGEN_SECRET_KEY`，任何接口都不返回明文，只显示后四位。

## 6. 任务引擎

### 6.1 状态机

```
blocked ──依赖完成──▶ ready ──领取──▶ leased ─┬─ 同步：running ──▶ succeeded / failed
                                            └─ 异步：submitting ──▶ submitted ──▶ succeeded / failed
任意未结束状态 ──取消──▶ canceled
租约过期：
  leased / running            → 回到 ready
  submitted（已有上游任务号）   → 其他 worker 接着轮询，绝不重复提交
  submitting（崩溃在提交中途）  → retry_safe 的供应商回到 ready；按次计费的供应商进入 needs_attention
needs_attention → 人工：重新查询 / 标记失败 / 强制重提（管理员）/ 手动挂接产物
```

- 进入 `submitted` 之前，先把上游任务号写库，再开始等待。
- 已经扣费的产物一律下载入库，包括被取消的任务。
- 超时按供应商实例配置（例如 ComfyUI 视频 2 小时）。超时后去上游核对状态，而不是直接放弃。
- 重试按供应商实例配置：autodl H3 不自动重发；ComfyUI、大模型、生图 API 可以退避重试。

### 6.2 领取与并发

- 每个资源池有固定数量的槽位行。worker 用 `SELECT … FOR UPDATE SKIP LOCKED` 先占槽位，再领取同池里优先级最高的 `ready` 任务。多台 worker 同时领取也不会超过并发上限。
- 异步任务在 `submitted` 期间继续占着槽位，直到出结果。这样 GPU 槽位数就等于真实的并发数。
- 领取顺序：优先级降序；同优先级时按 `policy.gpu_order`：
  - `run_first`（默认）：运行创建时间、镜头序号升序，先把一条片子跑完。
  - `round_robin`：多个运行轮流。
- 等待超过 30 分钟的任务，每 30 分钟优先级加 1，防止饿死。
- 唤醒：任务变为 `ready` 时发 `NOTIFY`；worker 也每 5 秒兜底轮询一次。

### 6.3 资源池（默认划分）

| 资源池 | 并发 | 说明 |
|---|---|---|
| `llm` | 8，另加每分钟请求上限 | 外部 API |
| `image-api` | 按生图供应商限额，例如 4 | 外部 API |
| `gpu-<机器>` | 每台 1 | ComfyUI；每台一个池 |
| `autodl-h3` | 例如 2 | 按次计费 |
| `ffmpeg` | 应用机 CPU 核数的一半 | 剪辑、接触表、检查 |

生图和视频不在同一个池：所有运行的关键帧都在 `image-api` 里并行跑，GPU 池按顺序一条条消费视频任务。

- 没有闸门时：某一镜的关键帧一完成，这一镜的视频任务就进入 GPU 队列，GPU 不用等整批图片出完。
- 有闸门时：等这一个运行的闸门通过（例如产品广告示例里的 `review`）。
- 需要一整批运行先全部出图、统一审过再跑视频时：打开 `policy.batch_barrier`。

多台 GPU 机：`video.comfy` 是一个实例组，成员是 `gpu1`、`gpu2` 等。视频任务交给最先空出来、且具备模板所需环境的那台。

### 6.4 探索期与生产期共用队列

agent 在探索期的零散任务也走同一个队列，`run_id` 为空。默认优先级比生产运行高 10：agent 在等结果，插到下一个即可，但不会抢占正在执行的任务。管理员可以调整。

### 6.5 进度与预计完成时间

- ComfyUI 通过 WebSocket 推送节点进度，换算成百分比写进任务。
- 预计完成时间 = 当前队列位置 × 历史平均耗时。历史耗时按（供应商实例、模板、分辨率、时长）分组统计。
- 网页和 CLI 通过 SSE 订阅任务和运行事件，不再每 5 秒全量轮询。

## 7. 供应商适配层

```python
class Adapter:
    kind: str            # llm | image | video | tts | music
    retry_safe: bool
    def estimate(task) -> Cost
    def run(task) -> Result                 # 同步：大模型、部分生图 API
    def submit(task) -> ProviderRef         # 异步
    def poll(ref) -> Progress | Result | Failure
    def cancel(ref) -> None
    def fetch(result) -> list[Artifact]     # 产物写入对象存储
```

| 适配器 | 来源 | 可安全重试 |
|---|---|---|
| `llm/openai-chat`、`llm/openai-responses`、`llm/anthropic-messages` | 新写 | 是 |
| `image/api` | 现有生图接入改写 | 是 |
| `video/autodl-h3` | 现有 `h3_client.py` 包装 | 否 |
| `tts/autodl-indextts` | 现有配音改写 | 否 |
| `music/api` | 现有音乐接入改写 | 视供应商而定 |
| `video/comfyui`（后续也可用于 image、tts） | 新写 | 是 |

ComfyUI 适配器：
- 模板是素材库里的一种素材：API 格式的工作流图，加上参数绑定和环境要求。
  ```json
  {
    "graph": {"...": "API 格式工作流"},
    "bindings": {"prompt": "6.inputs.text", "image": "12.inputs.image", "seed": "3.inputs.seed", "length": "20.inputs.length"},
    "outputs": ["9"],
    "requires": {"nodes": ["WanImageToVideo"], "models": ["wan2.2_i2v_14B.safetensors"]}
  }
  ```
  上面的节点名和模型名只是示意，按实际模板填写。
- 提交：只在占到空闲槽位后才提交一个，不把任务堆进 ComfyUI 自己的队列。插队、调优先级、取消都留在我们这边。
- 去重：请求里带 `client_id`，在 `extra_data` 里写我们的任务 ID。如果所用版本支持客户端指定 `prompt_id`，就直接用任务 ID 作为 `prompt_id`，崩溃后按 ID 查 `/history` 即可（接入时按实际版本核实）。
- 取消：正在执行的用 `/interrupt`，还在排队的用 `/queue` 删除。
- 产物：从 `/history/{prompt_id}` 找到输出文件，经 `/view` 拉回，写入对象存储。

花费：

| 供应商 | 计量 | 单价来源 |
|---|---|---|
| 大模型 | 输入、输出 token | 实例配置 |
| 生图 API | 张 | 实例配置 |
| autodl H3 | 视频秒数 | 实例配置（替换写死的 0.5 元/秒） |
| ComfyUI | GPU 执行秒数 | 实例配置的机器时薪，用于内部核算和比较工作流 |

预算在三处检查：发起运行前用试跑估算；运行中累计；探索期按设备每日预算。

## 8. 用户、权限与审计

| 角色 | 能做 |
|---|---|
| 管理员 | 全部，含供应商实例、资源池、用户、API 密钥、强制重提 |
| 审计员 | 看全部；审批闸门；发布、下线工作流版本；给 agent 留审计意见；批准设备 |
| 制作 | 用已发布工作流发起运行（含批量）、审片、下载、重跑单镜；注册自己的 agent 设备 |

- agent 设备归属某个用户，权限是“探索操作 + 工作流草稿 + 试跑”，不能发布，受每日预算约束。去掉“同时只能一台在线”的硬限制。
- 设备码流程：用户码改成 8 位 base32（如 `ABCD-EFGH`）；start 时另发一个只给 CLI 的轮询密钥；10 分钟过期；凭证只能领取一次；接口限流。CLI 打开的批准链接由 CLI 用自己的 `--base` 拼出，网页有对应的批准页，设备码已预填。
- 网页会话：HttpOnly cookie，可以多处同时登录，带过期时间。
- 服务账号：API 密钥绑定工作区和权限范围（`runs:write`、`runs:read`、`assets:write`），各自有限流和月预算。
- 公司若已有统一登录（飞书、企业微信、钉钉、LDAP），后续通过 OIDC 接入，第一期先用账号密码。
- 每个写操作都记事件，带操作者。网页提供活动流，按作品、运行、操作者、时间筛选。

## 10. 存储与媒体

- 媒体统一用短期签名地址（HMAC，默认 1 小时），网页、CLI、回调的接收方都能直接访问。S3 模式下配置单独的对外地址，或者由 API 流式转发。
- 对象键：`ws/{工作区}/works/{作品}/{条目}/文件`、`ws/{工作区}/runs/{运行}/{节点}/{条目}/文件`。
- 每个任务一个临时目录，上传完成后删除。
- 远程媒体通过 `pull` 任务拉进对象存储，不再把字节写进数据库。
- 产物保留策略（试跑产物、被驳回的候选图保留多久）待定，见第 14 节。

## 13. 默认策略（可调）

- agent 不能发布工作流，不能修改已发布版本。
- 探索期：每台设备有每日预算；单个任务预估花费超过阈值时，需要审计员在网页上批准。
- 生产期：闸门默认自动通过，每个工作流可以单独打开人工审批。
- autodl H3 不自动重发；ComfyUI 和外部 API 退避重试，最多 3 次。
- 探索期任务优先级比生产运行高 10。

## 14. 待定事项（不阻塞 M0、M1）

1. 大模型供应商和具体模型（三种协议都会支持，影响默认配置和单价）。

3. 公司统一登录用哪套（影响 OIDC 接入）。
4. 产物保留策略：试跑产物、被驳回的候选、中间文件分别保留多久。
5. GPU 机数量和型号（影响默认池配置和预计完成时间的初值）。
